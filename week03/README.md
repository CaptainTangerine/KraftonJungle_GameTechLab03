## 프로젝트 개요

2주차에 만든 DirectX 11 기반 3D 에디터를 확장해 월드 공간의 텍스트, 빌보드, SubUV 스프라이트 애니메이션과 디버그 렌더링을 구현했습니다. 폰트 아틀라스와 GPU 인스턴싱으로 텍스트를 출력하고, 카메라 방향에 따라 회전하는 텍스트·이미지 컴포넌트를 에디터에서 생성하고 편집할 수 있도록 연결했습니다.

원래의 독립 3주차 저장소는 현재 확인할 수 없지만, 공개 통합 저장소에 `git subtree`로 병합된 원본 커밋 그래프가 보존되어 있습니다. 해당 히스토리의 변경 파일과 실제 diff를 분석해 팀 전체 결과와 개인 기여를 구분했습니다. 공개 문서에는 팀원의 실명이나 개별 커밋 기록을 싣지 않았습니다.

## 팀 전체 구현

- 문자열을 해시·비교하고 엔진 객체 이름에 사용하는 `FName` 구조
- 솔리드·와이어프레임 뷰 모드와 요소별 표시를 제어하는 Show Flag
- 한글을 포함한 폰트 아틀라스 생성과 텍스트 렌더링
- 문자별 데이터를 묶어 처리하는 GPU 인스턴싱 기반 폰트 렌더링
- 월드 공간에 배치하는 `TextComponent`와 텍스트 정렬·줄바꿈·크기 조절
- 카메라를 향하는 빌보드와 화면 정렬 텍스트
- 아틀라스 프레임을 순환하는 SubUV 스프라이트 애니메이션
- 그리드·XYZ 축·선택 AABB·스포트라이트 범위 등 디버그 라인 렌더링
- Ctrl 다중 선택과 여러 오브젝트의 이동·회전·크기 일괄 변환
- 에디터 오브젝트 생성·속성 패널과 아이콘·레이아웃 개선

## 개인 기여

### 동적 라인 배치 렌더러

- 매 프레임 생성되는 디버그 라인을 하나의 `FBatchedLine`에 수집하는 구조를 구현했습니다.
- CPU에서 정점·인덱스를 모은 뒤 `D3D11_USAGE_DYNAMIC` 버퍼를 `WRITE_DISCARD`로 갱신해 여러 선을 한 번의 draw call로 출력했습니다.
- Render Collector가 라인을 수집하고 Render Bus가 단일 렌더 커맨드로 전달하며 Renderer가 line-list 패스로 그리는 흐름을 구성했습니다.
- 그리드와 XYZ 축, 선택 AABB, 스포트라이트 디버그 선이 동일한 배치 경로를 사용할 수 있도록 일반화했습니다.
- 별도의 HLSL 셰이더와 카메라 위치 상수 버퍼를 추가해 거리에 따라 그리드의 알파가 자연스럽게 감소하도록 했습니다.
- 다섯 칸마다 더 밝은 선을 사용해 그리드의 간격을 쉽게 구분할 수 있도록 개선했습니다.

### 월드 AABB 계산과 선택 시각화

- 월드 최소·최대 좌표를 보관하는 `FBoundingBox` 구조를 도입했습니다.
- 컴포넌트의 월드 행렬에서 방향 벡터와 스케일을 분리하고 큐브·평면의 회전된 축이 차지하는 범위를 합산해 AABB를 계산했습니다.
- 비균일 스케일이 적용된 구는 타원체의 각 월드 축 투영 길이를 이용해 AABB extent를 계산했습니다.
- AABB의 여덟 꼭짓점 중 한 비트만 다른 점을 연결해 열두 모서리를 라인 배치에 추가했습니다.
- 선택된 오브젝트의 AABB를 외곽선과 함께 표시해 피킹 범위와 변환 결과를 확인할 수 있게 했습니다.

### Ctrl 기반 다중 선택과 일괄 변환

- 단일 선택 포인터를 선택 컴포넌트 배열로 확장했습니다.
- Ctrl을 누른 상태에서 오브젝트를 클릭하면 선택 목록에 추가하고, 이미 선택된 오브젝트를 다시 클릭하면 제외하도록 구현했습니다.
- Ctrl 없이 클릭하면 기존 선택을 교체하고 빈 공간을 클릭하면 선택과 기즈모를 해제하도록 정리했습니다.
- 이동·회전·크기 변환을 선택 목록 전체에 적용하고 각 액터의 transform 갱신 경로를 호출했습니다.
- 선택된 모든 컴포넌트에 AABB와 선택 외곽선이 표시되도록 Render Collector의 컨텍스트를 확장했습니다.

### 빌보드와 화면 정렬 쿼드

- View 행렬에서 카메라의 Forward·Right·Up 기저 벡터를 추출해 화면을 향하는 회전 행렬을 구성했습니다.
- 초기에는 View 행렬에서 카메라 위치를 복원해 오브젝트-카메라 방향을 계산했고, 이후 화면 정렬 쿼드 방식으로 단순화해 카메라 pitch에 따른 기울어짐을 줄였습니다.
- 동일한 회전 방식을 텍스트, 빌보드 이미지, SubUV 컴포넌트에 적용했습니다.
- Full Billboard 모드에서는 Up 벡터까지 카메라 기저에 맞춰 화면 회전에 일관되게 대응하도록 확장했습니다.

### 렌더 상태와 리소스 수명 안정화

- Primitive 표시 옵션을 끌 때 그리드까지 사라지던 문제를 해결하기 위해 라인 패스의 셰이더와 렌더 상태를 독립적으로 바인딩했습니다.
- 와이어프레임 모드에서 선택 외곽선 패스를 건너뛰어 서로 다른 rasterizer state가 충돌하지 않도록 했습니다.
- 라인 패스 전후로 알파 블렌드와 기본 블렌드 상태를 명시적으로 전환했습니다.
- SubUV 셰이더와 라인 상수 버퍼의 Release 경로를 보완하고 프로젝트 파일의 누락된 소스 등록을 정리했습니다.

## 문제 해결

### 디버그 선마다 draw call이 늘어나는 문제

그리드와 AABB를 각각 즉시 렌더링하면 선의 개수만큼 상태 변경과 draw call이 증가합니다. 모든 선의 정점·인덱스를 프레임 단위로 모으고 동적 버퍼에 한 번 업로드한 뒤 단일 line-list draw call로 제출하도록 변경했습니다. 그리드, 선택 박스, 조명 범위가 같은 경로를 사용해 디버그 요소가 늘어나도 렌더 구조가 복잡해지지 않도록 했습니다.

### 회전·비균일 스케일 오브젝트의 AABB가 맞지 않는 문제

로컬 크기에 월드 위치만 더하는 방식으로는 회전된 큐브와 타원체의 범위를 표현할 수 없었습니다. 큐브와 평면은 월드 기저 벡터의 절댓값에 축별 half extent를 곱해 합산했고, 구는 회전된 타원체를 각 월드 축에 투영한 길이를 계산했습니다. 이를 통해 변환 후에도 피킹과 선택 박스가 실제 형상 범위를 감싸도록 했습니다.

### 다중 선택 상태와 기즈모 대상이 어긋나는 문제

단일 `TargetComponent`만 유지하면 여러 오브젝트를 선택해도 외곽선과 변환 대상이 일치하지 않았습니다. 선택 목록을 단일 기준으로 사용하고 마지막으로 추가한 대상을 기즈모 기준점으로 삼았습니다. 선택 추가·제거·해제와 이동·회전·크기 조절이 모두 같은 목록을 사용하도록 통합했습니다.

### 빌보드가 카메라 각도에 따라 기울어지는 문제

카메라 Right 벡터의 일부 성분만 사용한 초기 방식은 카메라 pitch와 roll에서 잘못된 방향을 만들었습니다. 카메라 위치를 역산하는 방식과 View 기저를 직접 사용하는 방식을 비교한 뒤, 화면 정렬이 필요한 요소에는 정규화한 Forward·Right·Up 벡터로 회전 행렬을 구성했습니다.

### 표시 옵션과 렌더 상태가 다른 패스에 전파되는 문제

Primitive 표시 여부와 wireframe 상태가 그리드·SubUV·외곽선에 의도치 않게 영향을 줬습니다. 라인, SubUV, 외곽선 패스의 조건과 셰이더·블렌드·래스터라이저 상태를 분리하고 패스 종료 시 필요한 상태를 복원했습니다.

## 회고

3주차에는 화면에 보조선을 그리는 단순한 기능도 렌더 파이프라인 전체의 구조와 연결된다는 점을 경험했습니다. 그리드와 AABB를 즉시 렌더링하는 대신 수집·업로드·제출 단계를 분리하면서, 작은 디버그 기능을 재사용 가능한 렌더 패스로 확장할 수 있었습니다.

다중 선택과 빌보드는 렌더링 결과와 에디터 상태, 수학적 좌표 변환이 동시에 맞아야 하는 기능이었습니다. 선택 목록을 단일 상태로 정리하고 모든 변환과 시각화가 이를 참조하도록 만들었으며, View 행렬의 기저 벡터를 직접 확인하면서 카메라와 오브젝트의 좌표계를 맞췄습니다. 기능을 추가하는 것뿐 아니라 패스 간 상태 누수와 GPU 리소스 해제까지 마무리하며 에디터 렌더링의 수명 주기를 더 깊이 이해한 주차였습니다.
